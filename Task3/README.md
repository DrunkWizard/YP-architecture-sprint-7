## Нефункциональные требования для PropDevelopment

Наблюдения: 
- Хранение бимоетрии для работы домофонов. Это персональные данные с которыми нужно быть осторожными. 
- Хранение номеров автомобилей для открытия шлагбаума. Сами по себе не являются персональными данными, но могут помочь определить личность человека вместе с другими данными. 
- Взаимодействие с внешним API требует зашифрованного канала

### Требования к безопасности: 

- Безопасные каналы связи TLS
- Хранение данных беометрии и гос номеров в зашифрованном виде с ротацией ключей
- Аудит действий с персональными данными
- Соответствие требованиям законодательства
- Проведение аудита системы
- Пентесты 

### Требования к аутентификации и авторизации: 

1. Для пользователей:
    - Многофакторная аутентификация
    - Ролевая модель доступа, следующая прицнипу наименьших привелегий
    - OAuth 2.0 для интеграции с мобильным приложением
2. Для системной интеграции:
    - Mutual TLS для аутентификации между системами
    - JWT-токены с ограниченным временем жизни и возможностью убрать доступ вручную
    - API-ключи с IP-фильтрацией для партнёрских систем 

### Требования к взаимодействию между системами

1. Архитектурные принципы
    - Прицнипу наименьших привелегий
    - Circuit breaking
    - Ретраи
    - Тестирования

2. Протоколы и форматы
    - GRPC для синхронного взаимодействия
    - Ошибки в формате RFC 7807
    - Kafka для асинхронных взаимодействий с DLQ
